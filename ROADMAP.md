- [x] Windows lifecycle defect (owner manual acceptance on published main, class A): **Restart and Stop of a running instance returned `500 {"error":"not supported by windows"}` whenever the GoAl server process has no console** (service / headless / detached launch). Forensic chain: UI Restart → `POST /api/v1/instances/{id}/restart` → `InstanceService.RestartInstance` → `Supervisor.Restart` → `InstanceController.Restart` → `stop()` → `Manager.Stop` → `windowsControl.GracefulStop` (`internal/platform/platform_windows.go`): `GenerateConsoleCtrlEvent(CTRL_BREAK, pid)` fails without a console (`ret=0`, `ERROR_INVALID_HANDLE` — proven with an instrumented build in both launch modes), and the fallback `proc.Signal(os.Interrupt)` is structurally unsupported by Go on Windows (`os/exec_windows.go`: only `Kill` is implemented; every other signal returns `syscall.EWINDOWS` = "not supported by windows") — the raw OS error propagated to the API verbatim, Restart aborted before launching the new process (model left stopped), and Stop only succeeded via the 5 s ForceKill (Job Object close) safety net while still reporting 500. Start was unaffected (it signals nothing). Fix aligns with ADR 001 ("Attempt a console control event for graceful shutdown where compatible, then terminate the Job Object"): on GCE failure the stop now escalates **immediately** to Job Object termination (no broken signal fallback, no spurious error). Shipped: `d23fe67` + CI run 33120698784 (success, 2026-08-28): `platform_windows.go` GracefulStop fallback → `ForceKill()`; regressions: `internal/platform/gracefulstop_windows_test.go` (GCE-inapplicable path returns no error — deterministic in both console and headless; real-process termination on both paths) + `core.cjs` §7.4 (Start → Restart of a running instance → still running with a new PID — the exact owner repro; pre-fix coverage gap: §7.1 asserted only the HTTP status and §6's tolerant Stop test masked the error).
