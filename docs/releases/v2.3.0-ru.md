# GoAl v2.3.0 — Release Notes (RU)

GoAl v2.3.0 — промежуточный релиз с двумя новыми возможностями: **мониторинг ресурсов**
(CPU / RAM / GPU / RAM процессов) и **единый Commands API** для управления жизненным циклом.
Принят Owner вручную 2026-11-24 (v2.3.0-rc2: все 8 проверок покомпонентных действий и видимости
процессов PASSED на реальном оборудовании Windows).

## Мониторинг ресурсов (ADR 025 / ADR 026)

**API (только чтение, никаких управляющих действий):**

- `GET /api/v1/system/gpu` — телеметрия NVIDIA через `nvidia-smi` (ADR 025, RES-02A): для каждого
  GPU — модель, драйвер, VRAM всего/используется/свободно. Только NVIDIA; read-only.
- `GET /api/v1/system/resources` — универсальный мониторинг (ADR 026, RES-03A/03B): вендор-нейтральная
  модель с трёхуровневой декларацией возможностей по каждой метрике — `supported` (статический факт),
  `available` (источник обнаружен в этом запросе), `sampled` (значение получено в этом запросе).
  Провайдеры: `system` (CPU/RAM) и `nvidia` (VRAM). Значения опрашиваются по одному разу на запрос:
  без фоновых опросов, без кеша, без «последнего хорошего» значения. Неудача одного источника
  не обесценивает остальные: состояние ответа —
  `ok` / `partial` / `unavailable` / `measurement_failed`.
- **Системные CPU/RAM** (RES-03B): RAM всего/доступно/используется (значение `used` — расчётное,
  помечено `estimated`), число ядер, утилизация CPU (два счётчика в окне ~250 мс внутри запроса).
  Работает на Windows и Linux; на macOS — RAM (`available` через `vm_stat`, оценка) с запасом по возможностям.
- **RAM процессов (per-process RSS)** (RES-05A/06, ADR 026 A-026-1): в `processes[]` ответа
  `GET /api/v1/system/resources` — RSS каждого процесса instance в нетерминальном
  состоянии (`starting` / `running` / `stopping` / `orphan`), с привязкой к instance / модели /
  runtime / элементу пайплайна. Для недоступного значения — причина (`pid_not_assigned`,
  `process_exited`, `identity_mismatch`, `identity_unconfirmed`, `counter_unavailable`), никогда —
  выдуманное «0». Терминальные процессы в списке отсутствуют. На macOS метрика не поддерживается.

**Интерфейс:**

- Новая страница **«Ресурсы»** (раздел «Дополнительно»): загрузка CPU и количество ядер, RAM
  всего/используется/доступно и процент, по одной карточке на каждый GPU (вендор, модель, драйвер,
  класс памяти, VRAM всего/используется/свободно и процент), CPU-only установка отображается как
  штатное состояние, измеренный «0» отличается от «нет данных». Обновление — ручное и каждые 5 секунд,
  **только пока страница открыта** (уход со страницы останавливает опрос).
- **RAM процессов на странице «Ресурсы»** (RES-06): карточки живых процессов с RSS и привязкой
  к модели/пайплайну; после остановки процесса карточка исчезает.
- **Локализация страницы «Ресурсы»**: RU-подписи доведены до конца — «Рантайм», «ОЗУ процесса»,
  «Видеопамять: всего/используется/свободно», бинарные единицы ГиБ/МиБ/КиБ, десятичный разделитель
  по локали (в RU — запятая). Под processes-разделом добавлено пояснение: резидентная память
  процесса может включать общие страницы и смонтированные в память файлы моделей.
  Значения метрик, пороги единиц (1024) и расчёты не изменены; EN-словарь сохранён.

## Commands (ADR 024, Stage 1)

- Единая точка управления `POST /api/v1/commands/execute` (аутентификация + CSRF). Словарь из девяти
  команд: `model.start` / `model.stop` / `model.restart`, `instance.start` / `instance.stop` /
  `instance.restart`, `pipeline.start` / `pipeline.stop` / `pipeline.restart`.
- Команды делегируют существующим путям жизненного цикла (ADR 017, единый arbitr): команды не создают
  второй механизм управления процессами и не меняют семантику состояний.
- UI: покомпонентные **Start / Stop / Restart** на чипах элементов пайплайна (G3-RES-01 UI,
  ADR 024 D-11/D-12); остановка и перезапуск доступны для точно привязанного работающего компонента,
  запуск — для корректно завершённого (`exited` / `failed`) компонента того же пайплайна.

## Исправления

- **Покомпонентные Start/Stop/Restart сохраняются после повторного запуска пайплайна** (`9059e4d`,
  уточнение ADR 024, 2026-11-24): после второго и последующих циклов «запуск → остановка» на чипе
  элемента пайплайна снова появлялась только информационная иконка — выбор экземпляра требовал ровно
  одну запись истории, хотя история по контракту хранится навсегда. Теперь при точной привязке
  (precise attribution) работающий компонент показывает Stop/Restart, завершённый — Start; при
  нескольких активных компонентах одной записи управление намеренно недоступно (без произвольного
  выбора процесса). Команды уровня пайплайна и семантика backend-команд не изменены. Принято Owner
  на ручной приёмке v2.3.0-rc2 (2026-11-24).
- Стабилизация тестов Commands: синхронизация mock-хранилища экземпляров (мьютекс) — устранение
  гонки в тестовой инфраструктуре (`53d1ef4`).
- Тест боковой панели синхронизирован с новым количеством разделов после добавления «Ресурсы» (`36dba42`).
- Документация: copy-safe примеры конфигурации (без mojibake при копировании) в руководстве по
  конфигурации (`4579325`); сверка ROADMAP/BACKLOG-статусов после публикаций Stage 1 (`a8f8f3e`, `2e4b8d4`).

## Ограничения платформ

- **GPU:** поддержан только NVIDIA через `nvidia-smi` (нужны драйвер и утилита в системе). Провайдеры
  AMD / Intel / Apple GPU — не реализованы. Отсутствие `nvidia-smi` — штатный `unavailable`, ошибка
  драйвера — ограниченная причина; сбой измерения не меняет declared-supported.
- **RAM процессов:** Windows и Linux (Linux: verify→read→re-verify по /proc). **macOS — не поддерживается**
  (метрика объявляется как unsupported). Точная привязка процесса к instance требует совпадения
  исполняемого файла и времени старта (допуск ±5 c); неподтверждённая идентичность не выдаётся за факт.
- **CPU/RAM:** Windows / Linux — измерение; macOS — RAM с оценочным `available` (`vm_stat`).
  Утилизация CPU внутри запроса добавляет к времени ответа фиксированное окно (~250 мс).
- **Бинарные артефакты не подписаны** (Authenticode не настроен): Windows SmartScreen может
  предупреждать о неподписанном исполняемом файле.

## Известные проблемы

- **C-7 (ADR 026):** телеметрия реального NVIDIA визуально подтверждена Owner на хосте с двумя
  RTX 5060 Ti (Owner-скриншоты, ручная приёмка v2.3.0-rc2, 2026-11-24); явное числовое сверка с
  выводом `nvidia-smi` ещё не выполнена — C-7 остаётся открытым.
- **macOS:** приёмка на реальном macOS не выполнялась (сборка кросс-платформенная, тестирование на
  машинах Windows/Linux).
- **VRAM по компонентам** (RES-02B, привязка VRAM к отдельным instance) — не входит в этот релиз;
  лимиты, планирование и приоритеты ресурсов — вне области (ADR 015 заморожен).
- Часть галочек ROADMAP/BACKLOG по ресурсному треку остаётся открытой до релизной сверки
  (RES-03 — до macOS-приёмки и C-7; RES-04 — до фиксации Owner acceptance).
